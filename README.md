# Theme Hub for Torn

23 colour themes for torn.com, switchable from the toolbar popup. Pure CSS
restyling of the page you are already looking at.

---

## Rules compliance

Torn's scripting-abuse rule allows software that "rel[ies] on data from ... a
page that you have manually loaded and are actively viewing", and forbids
non-API requests, scraping unviewed pages, CAPTCHA bypass, extracting data from
unfocused pages, and undisclosed functionality.

This extension:

| Rule | How this extension stands |
|---|---|
| No non-API requests to Torn | Makes **zero** requests of any kind. There is no `fetch`, `XMLHttpRequest`, `WebSocket`, `sendBeacon` or `<img>`-ping anywhere in the codebase. |
| No scraping unviewed pages | Only ever runs in the tab you have open. It adds a `<style>` element of colour variables and a few `data-thm` attributes, and reads no game data at all. |
| No CAPTCHA interference | Does not touch CAPTCHA, forms, or any game action. |
| No extracting data from unfocused pages | Nothing is extracted, and nothing is sent anywhere. Settings live in `browser.storage.local`, which never leaves your machine. |
| No undisclosed functionality | Everything shipped is readable, unminified JS and CSS. Two of the CSS files are generated by the scripts in `tools/`, and they are plain CSS too. See [PRIVACY.md](PRIVACY.md). |

The one feature that reads anything is **Inspect page palette**, which lists the
CSS custom properties in stylesheets the page has *already loaded into memory* —
the same thing devtools shows you — and copies them to your clipboard. It fires
only when you click the button, and issues no request.

You can verify the "no requests" claim for yourself: open devtools → Network,
filter to the extension, and browse Torn. It stays empty.

- **Firefox:** `about:debugging#/runtime/this-firefox` → *Load Temporary

## Releasing an update

1. Bump `version` in `manifest.json` (stores reject a version they have
   already seen).
2. If you saved new Torn CSS into `torn_css/`, regenerate:
   ```bash
   python tools/gen_torn_vars.py
   ```
   ```bash
   python tools/gen_torn_rules.py
   ```
3. Build the store packages. This runs the safety checks and refuses to package
   if any fail:
   ```bash
   python tools/build_release.py
   ```
   → `dist/theme-hub-for-torn-<version>-firefox.xpi` and `...-chrome.zip`
4. Upload each file as a new version in its store's developer dashboard.
   Installed copies update themselves.

Store listing text, permission justifications, reviewer notes and the forum
announcement are in `store/`. To re-render the screenshots (with the project
served on port 8778):
```bash
bash tools/render_shots.sh
```

**Never publish `torn_css/`.** It contains Torn's own stylesheets, used only as
generator input. It is excluded from the packages and from git.

## Using it

Click the toolbar icon:

- **Theme grid** — click a card to apply instantly, no page reload
- **Master switch** — off restores Torn's own stylesheet completely
- **Hide backdrop** — removes Torn's decorative page-background photo, which
  fights most palettes (on by default)
- **Theme chat panel** — the chat sidebar is React with hashed class names, so
  it is the most fragile part; turn it off if it looks wrong after a Torn update
- **Tone down images** — desaturates page imagery so avatars and faction tags
  sit more quietly inside dark themes
- **Also theme jail / hospital / travel** — off by default: Torn re-tints ~80
  colours in those states to tell you where you are, and those tints are kept
  unless you tick this

### If nothing changes on torn.com

1. Hard-reload the Torn tab (`Ctrl+Shift+R`) — the content script only attaches
   to pages loaded after the extension was installed.
2. In Firefox, open `about:addons` → Theme Hub for Torn → **Permissions** and make
   sure *Access your data for sites in the torn.com domain* is enabled. Firefox
   MV3 treats host permissions as opt-in.
3. Check the master switch in the popup is on.

Themes work whether Torn's own dark mode is on or off — the extension overrides
both.

## Adding a theme

Each theme is ~10 lines in `src/themes.js`. Add an entry and its id to
`TORN_THEME_ORDER`:

```js
mytheme: tornThemeMake('My Theme', 'dark', {
  bg:     '#10131a',   // page background
  bg2:    '#171b24',   // header / sidebar / title strips
  surface:'#1b202c',   // content panels
  surfaceAlt: '#222839', // inputs, quotes, alternating rows
  text:   '#c6cede',
  dim:    '#7c869b',   // timestamps, secondary labels
  heading:'#e6ebf5',
  link:   '#6fa8ff',
  accent: '#3b82f6',   // buttons, active nav, progress fills
  border: '#2a3141'
}),
```

`tornThemeMake` fills the rest of the token set from those. Override any of
`header`, `sidebar`, `titlebar`, `titleText`, `headerText`, `linkHover`,
`accentText`, `shadow`, `scrollThumb` individually if you want finer control.

Money colours (`positive` = green, `negative` = red) are worked out
automatically: the hue is kept, and the lightness is adjusted until the colour
reaches 4.5:1 contrast against the theme's sidebar and panels. Pass `positive`
or `negative` to override them.

### Previewing without reloading Torn

`test/fixture.html` renders a Torn forum page using **Torn's real stylesheets**
from `torn_css/` plus the extension's CSS, with a theme picker and a Torn
dark-mode toggle. Nothing in it contacts torn.com.

```bash
python tools/build_fixture.py
python -m http.server 8778
```

Open `http://localhost:8778/test/fixture.html` (URL options: `?theme=nord`,
`&dark=1`, `&off=1`). The build stamps every `src/` file with its modification
time, so edits always show on refresh.

## How it works

```
src/themes.js         palette data (shared by popup + content script)
src/content.js        reads storage -> writes --thm-* tokens + data-thm-* flags on <html>
src/torn-vars.css     GENERATED  re-points Torn's own ~370 colour variables at the tokens
src/torn-rules.css    GENERATED  overrides ~1,300 colours hardcoded in Torn's stylesheets
src/theme-engine.css  hand-written rules for what the generators cannot see
                      (React build CSS with hashed class names, chat, TornTools notes)
src/popup.*           the picker
tools/                the generators + fixture builder
torn_css/             Torn's stylesheets, saved by hand from pages you visited
```

Load order is `torn-vars` -> `torn-rules` -> `theme-engine`. Everything is
scoped under `html[data-thm]`, so it is all inert until a theme is on, and
switching off leaves Torn's own CSS untouched.

### The two generators

**`tools/gen_torn_vars.py`** reads Torn's `:root { ... }` (light) and
`:root .dark-mode { ... }` (dark) variable blocks. Each neutral grey is mapped
onto a ramp built from the theme:
`bg -> surface -> surface-alt -> border -> text-dim -> text -> heading`.
Dark-mode values are the reference, because there lightness maps cleanly onto
role. Blues in `*blue*`/`*link*` variables become `link`, and focus rings become
`accent`. Every other saturated colour is left alone, because it means
something: money, status, rarity, errors.

The overrides sit on `<body>` with `!important`, because Torn declares its dark
variables on `:root .dark-mode` / `:root .r.dark-mode`, which is `<body>`, so
anything set on `<html>` would lose.

**`tools/gen_torn_rules.py`** walks every rule in every saved stylesheet and
re-emits colour declarations with their greys swapped for tokens, keeping the
original selector (prefixed with `html[data-thm]`) and the original order, so
Torn's hover and active states still cascade correctly. Here a grey's meaning
depends on the **property** and on which **mode** the rule was written for. In a
light-mode rule `#f2f2f2` is a panel and `#333` is text. A dark `#444`
background is a "dark island" (title bar, tooltip), and its white text is
mapped to `titlebar-text` so the pair stays legible in every theme.

### Adding coverage for more pages

Anything that looks untouched is using CSS that is not in `torn_css/` yet.

1. On the Torn page that looks wrong, open devtools -> **Network**, filter to
   **CSS**, and reload.
2. Save each stylesheet into `torn_css/` (right-click -> *Open in new tab*, then
   `Ctrl+S`). File names do not matter, since files are identified by their
   content.
3. Regenerate and reload the extension:

```bash
python tools/gen_torn_vars.py
python tools/gen_torn_rules.py
```

Then press **Reload** on the extension in `about:debugging`.

Worth grabbing first: the React bundles under `/builds/*/app.*.css` (sidebar,
header, chat, profile-mini, text-editor) and the forum set under
`/css/style/forums/`. Those are not in `torn_css/` yet, which is why the sidebar,
header and chat still rely on the hand-written rules.

The React bundles use hashed class names (`sidebar___c4dEc`). The generator
keeps them exact, so they match precisely today. When Torn ships a new build,
save the new bundle and rerun.

## Known limits

- **Generated coverage is only as wide as `torn_css/`.** See above.
- **Self-repair has a hard limit.** If another script removes the theme's
  `data-thm` attributes or palette `<style>`, `content.js` puts them back, but
  at most 5 times in 10 seconds. If something keeps undoing it, the extension
  stops re-applying on that page and logs
  `[Theme Hub for Torn] Another script keeps removing the theme...` to the
  console. (v1.3.0-1.4.2 had no limit and could lock up the browser in an
  endless back-and-forth with another script. Fixed in 1.4.3.)
- **The Torn wiki is deliberately left alone.** `wiki.torn.com` is a separate
  MediaWiki site with its own stylesheet, so the manifest excludes it, and
  `content.js` also switches off on any MediaWiki page (`body.mediawiki`) served
  from another Torn address.
- **TornTools is deliberately left alone.** It owns the `--tt-*` variable
  namespace and has its own theming. This extension uses `--thm-*` and only
  nudges the sidebar notes box into line.
- **Semantic colours are preserved on purpose.** Money, honor bars, status
  banners, error states, item rarity, and `.t-red`/`.t-green` keep Torn's
  values, because recolouring them would hide information.
- **Brief flash on load.** Settings come from async storage, so a page can paint
  in Torn's colours for a frame before the theme lands.
- **Contrast.** All 23 themes are checked at >= 3:1 for every text element in
  the fixture, in both Torn light and dark mode. Pages outside the fixture have
  not been checked the same way.
